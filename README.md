# Claude Code Harness

Claude Code 기반 개발 작업을 더 일관되고 안전하게 진행하기 위한 작업 규칙 저장소입니다.

이 저장소의 목적은 Claude Code에게 매번 긴 설명을 반복하지 않고, 정해진 작업 규칙을 기준으로 분석, 계획, 구현, 검증을 수행하도록 하는 것입니다.

---

## 목적

이 저장소는 다음 문제를 줄이기 위해 사용합니다.

1. Claude Code가 바로 구현부터 시작하는 문제
2. 한 번에 너무 많은 파일을 수정하는 문제
3. PR 범위가 커지고 목적이 섞이는 문제
4. DB 변경이나 migration을 충분한 검토 없이 진행하는 문제
5. 매번 긴 프롬프트를 작성해야 하는 비효율
6. 구현 후 검증 없이 완료로 판단하는 문제

---

## 핵심 원칙

Claude Code는 모든 작업에서 아래 원칙을 우선 적용합니다.

```text
분석 없이 구현하지 않는다.
승인 없이 파일을 수정하지 않는다.
작업 범위를 작게 나눈다.
검증 없이 완료라고 말하지 않는다.
```

## 각 문서의 역할

### `harness/common.md`

모든 작업에 공통으로 적용되는 기본 작업 규칙입니다.rea

주요 내용:

```text
- 요구사항 확인
- 현재 상태 분석
- 변경 영향 범위 정리
- 작업 계획 작성
- 사용자 승인 대기
- 구현
- 검증
- 결과 보고
```

모든 Claude Code 작업은 기본적으로 이 문서를 먼저 기준으로 삼습니다.

---

### `harness/git.md`

Git 및 PR 단위 작업을 위한 형상관리 규칙입니다.

주요 내용:

```text
- 하나의 PR에는 하나의 목적만 포함
- 기능 구현, 리팩토링, 문서 수정, DB 변경을 한 PR에 섞지 않음
- 사용자 승인 없이 git add, commit, push 금지
- PR 제목과 설명 초안 작성
- 변경 파일과 검증 방법 보고
```

Claude Code가 작업 범위를 과하게 확장하지 않도록 통제하는 역할을 합니다.

---

### `harness/db.md`

DB 구조, migration, schema 변경을 다룰 때 사용하는 규칙입니다.

주요 내용:

```text
- migration 작성 전 현재 DB 구조 분석
- 기존 데이터 영향 범위 확인
- rollback 가능성 검토
- API, UI, 타입 정의 영향 확인
- 사용자 승인 전 migration 파일 생성 금지
- 운영 DB 직접 변경 금지
```

DB 변경은 코드 수정보다 리스크가 크기 때문에 별도 하네스로 분리합니다.

## 사용 방법

각 프로젝트에서 Claude Code에게 아래처럼 지시합니다.

```text
이 프로젝트는 claude-code-harness 기준으로 진행합니다.

먼저 아래 문서를 읽고 적용 규칙을 요약하세요.

- harness/common.md
- harness/git.md

아직 구현하지 말고, 현재 코드 구조 분석과 PR 단위 작업 계획만 작성하세요.
```

DB 작업이 포함된 경우에는 다음 문서를 추가합니다.

```text
- harness/db.md
```

예시:

```text
이 작업은 DB 구조 변경이 포함됩니다.

claude-code-harness의 다음 문서를 기준으로 진행하세요.

- harness/common.md
- harness/git.md
- harness/db.md

아직 migration을 작성하지 말고, 먼저 현재 DB 구조와 변경 영향 범위, rollback 가능성을 검토하세요.
```

## 권장 작업 흐름

Claude Code 작업은 아래 흐름을 따릅니다.

```text
1. 관련 harness 문서 확인
2. 적용할 규칙 요약
3. 현재 코드 구조 분석
4. 변경 영향 범위 정리
5. PR 단위 작업 계획 작성
6. 사용자 승인 대기
7. 구현
8. 검증
9. 결과 보고
```

---

## 승인 전 금지 작업

Claude Code는 사용자 승인 없이 아래 작업을 수행하지 않습니다.

```text
- 파일 생성
- 파일 수정
- 파일 삭제
- 패키지 설치
- DB migration 작성
- DB migration 실행
- 환경변수 변경
- git add
- git commit
- git push
- 배포 명령 실행
- 기존 기능 제거
```

---

## 승인 문구

아래와 같은 명시적 승인 문구가 있을 때만 실제 구현을 진행합니다.

```text
진행
구현 진행
PR 진행
수정 진행
적용해
DB 변경 진행
migration 작성 진행
```

단, 작업 범위는 사용자가 승인한 내용 안으로 제한합니다.

## Claude Code에 전달할 기본 프롬프트

새 작업을 시작할 때 아래 문구를 사용할 수 있습니다.

```text
이 프로젝트는 claude-code-harness 기준으로 진행합니다.

먼저 다음 문서를 읽고 적용 규칙을 요약하세요.

- harness/common.md
- harness/git.md

아직 구현하지 마세요.
현재 코드 구조를 분석하고, 변경 영향 범위와 PR 단위 작업 계획만 작성하세요.
내가 "진행"이라고 말하기 전까지 파일을 생성, 수정, 삭제하지 마세요.
```

DB 작업이 포함된 경우:

```text
이 작업은 DB 변경 가능성이 있습니다.

다음 문서를 기준으로 진행하세요.

- harness/common.md
- harness/git.md
- harness/db.md

아직 migration 파일을 작성하지 마세요.
먼저 현재 DB 구조, 관련 코드, 변경 영향 범위, rollback 가능성을 분석하고 계획만 작성하세요.
```

Claude Code는 구현 후 아래 형식으로 결과를 보고합니다.

```text
## 작업 결과

### 변경한 파일
-

### 변경 내용
-

### 검증 결과
- 실행한 검증:
- 결과:

### 실행하지 못한 검증
- 항목:
- 이유:

### 남은 리스크
-

### 다음 단계 제안
-
```

## 이 저장소의 범위

현재 저장소는 최소 하네스만 포함합니다.

포함된 항목:

```text
- 공통 작업 규칙
- Git / PR 형상관리 규칙
- DB / Migration 규칙
```

아직 포함하지 않은 항목:

```text
- UI/UX 하네스
- 콘텐츠 정제 하네스
- 테스트/QA 하네스
- 보안 하네스
- 문서화 하네스
- Claude Code hooks
- slash command
```

필요해질 경우 실제 프로젝트 경험을 바탕으로 점진적으로 추가합니다.

---

## 운영 원칙

이 저장소는 처음부터 완벽한 규칙 모음을 목표로 하지 않습니다.

목표는 다음과 같습니다.

```text
1. 반복되는 Claude Code 지시를 줄인다.
2. 작업 시작 전 분석과 계획을 강제한다.
3. PR 단위로 작은 작업을 유지한다.
4. DB 변경 리스크를 낮춘다.
5. 검증 가능한 결과 보고를 만든다.
```

규칙이 과도하게 길어지면 오히려 Claude Code의 작업 효율이 떨어질 수 있으므로, 문서는 짧고 실행 가능한 형태로 유지합니다.

## 추천 적용 방식

프로젝트 루트에 `CLAUDE.md`를 두고, 이 저장소의 하네스 문서를 참조하도록 설정하는 방식을 권장합니다.

예시:

```text
이 프로젝트는 Claude Code 기반 개발을 진행합니다.

작업 전 다음 하네스 문서를 기준으로 합니다.

- claude-code-harness/harness/common.md
- claude-code-harness/harness/git.md
- claude-code-harness/harness/db.md

기본 규칙:
1. 바로 구현하지 않습니다.
2. 먼저 분석과 계획을 작성합니다.
3. 사용자가 "진행"이라고 말하기 전까지 파일을 수정하지 않습니다.
4. 작업은 PR 단위로 진행합니다.
5. 구현 후 검증 결과를 보고합니다.
```
